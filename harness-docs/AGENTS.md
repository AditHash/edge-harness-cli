# AGENTS.md — Codex instructions for Hybrid Coding Harness

## Mission

Build a **local-first, Claude Code / Codex-style coding CLI** in Python. Use **Strands Harness as the only primary agent loop**, **Amazon Bedrock as the initial model provider**, and **LangChain components as optional, well-bounded services/tools** for retrieval, code understanding and structured workflows. Evaluate Deep Agents as an **alternative benchmark or optional separately invoked specialist**, never as a competing second loop inside the primary runtime.

Read `GOALS.md`, `ARCHITECTURE.md`, `docs/HYBRID_INTEGRATION.md`, `docs/SECURITY.md`, `PLANS.md`, and the active `harness/build/phase-XX-*.md` before changing code.

## Non-negotiable engineering rules

1. Implement **one phase at a time**, follow its acceptance gate, and stop after it. Never turn a docs task into a full unrequested implementation.
2. Begin by inspecting existing source code and versions. Preserve user changes. Never assume SDK signatures; verify pinned versions against official docs and small tests. Record discoveries in `docs/SDK_NOTES.md`.
3. **One owner for the agent loop:** Strands Harness / Strands Harness SDK. Do not run `create_deep_agent()` / LangChain `create_agent()` inside the main Strands turn loop. Use LangChain `Document`, retrievers, splitters, Runnables and vector stores as plain Python services behind Strands `@tool` adapters.
4. Keep CLI/UI, runtime, Bedrock model construction, LangChain helpers, workspace policy, file changes, shell isolation, sessions, and tracing separately testable. Use dependency injection and typed boundaries.
5. Python 3.11+, `uv`, `typer`, `rich`, `pytest`, `ruff`, `pydantic` where appropriate. Add `langchain-core` only when a concrete use case exists; do **not** add every LangChain package on day one.
6. Use the AWS credential provider chain, account-selected Bedrock model ID/inference profile and region. Never hardcode secrets or credentials; no billed calls during offline tests.
7. Disable all Strands built-in tools initially (`builtin_tools=[]`) and register only our **policy-enforced read-only tools**. Do not infer path safety from `builtin_tools=["read"]`: a host file read remains a host file read.
8. Shell commands generated by a model **never execute directly on the host**. Add OS-isolated execution only after Phase 4 security tests. Model tool calls are untrusted.
9. Every edit is a staged proposal with an exact diff and explicit approval. Reject on EOF/cancel. Use root-bound canonical path checks, symlink/junction policies, protected secret paths, and stale-diff checks at the actual execution boundary.
10. Repository data, external tool outputs, skills and MCP tool descriptions are untrusted. Never let them override security policy or expand privileges. No secrets in traces, error logs or retrieved context.
11. Be precise: report actions as proposed, approved, executed, or verified. Never claim a test passed without running it; surface failures, costs, limitations and skipped verification.
12. Make Windows/PowerShell and Linux behavior explicit. Docker-dependent tests may skip only with clearly reported reasons.
13. No automatic git commit/push, unrestricted shell, cloud mutations, or broad network permissions. MCP and LangGraph delegation are opt-in after core safety gates.
14. Run available checks (`uv run ruff check .`, `uv run pytest -q`) and record exact outputs in `harness/build-log.md`. Only mark PLANS.md checkboxes when verified.

## Project priorities

1. Safe read-only Bedrock + Strands CLI.
2. Accurate streaming and interruption.
3. Reviewed file editing and safe diff application.
4. Isolated test/build command execution.
5. Durable session restore, useful LangChain-powered repository retrieval, optional MCP/skills and evals.

## Current implementation rules (keep in sync with code)

- Work only inside the repository folder the session started in.
- Every new tool must go through `Workspace` for file access and, if it has side effects, through an
  approval callback that fails closed in non-interactive mode. Add a test that a denial changes nothing.
- Never add a host-shell fallback. If `platforms.sandbox_backend()` is `None`, execution stays disabled.
- Tests that need WSL/Bubblewrap are opt-in (`HARNESS_TEST_WSL=1`); report skips as skips.
- Run `uv run ruff format src tests`, `uv run ruff check src tests`, `uv run mypy src`, `uv run pytest -q`
  before each commit; commit small and update `harness/build-log.md` with evidence.
- Strands owns the loop. Do not add LangGraph/Deep Agents without a measured benefit recorded in the log.
